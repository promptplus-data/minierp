# ภาคผนวก: ไฟล์ใบส่งของ / คำสั่งซื้อ สำหรับ On-premise

สถานะ: **Draft v0.1 (2026-10-27)** · On-premise edition (ใช้ใน Cloud ได้ด้วยสำหรับผู้จำหน่ายที่ไม่ใช่ SCG)

On-premise ไม่เรียก API ของ SCG ใด ๆ (ดู [`README.md` §1](README.md#1-ขอบเขตและ-edition)) ร้านรับของด้วย "ซื้อเข้าแบบบันทึกเอง" (REQ-M05-06, `POST /api/stock/receipts`) ไฟล์นี้กำหนดรูปแบบไฟล์ **generic** ที่ร้านนำเข้าเพื่อสร้าง **ใบรับของร่าง** แทนการคีย์ทีละบรรทัด ไฟล์มาจากระบบใดก็ได้ (export จากผู้แทนจำหน่าย, ใบสั่งซื้อที่ส่งทางอีเมล, Excel ของร้านเอง)

> ข้อกำหนด build: ฟีเจอร์นี้อยู่ใน on-prem bundle ดังนั้นโค้ด ข้อความ UI และชื่อไฟล์ของฟีเจอร์ **ห้ามมีคำว่า Prompt Plus** (`scripts/check-onprem.mjs`) ใช้ชื่อ "นำเข้าใบส่งของ" / `delivery-import`

---

## 1. รูปแบบไฟล์

| รายการ | ข้อกำหนด |
|---|---|
| ชนิด | `.csv` หรือ `.xlsx` (อ่าน sheet แรก หรือ sheet ที่ผู้ใช้เลือก) |
| Encoding (CSV) | UTF-8, UTF-8 with BOM, TIS-620 (Windows-874) — ตรวจอัตโนมัติ: มี BOM → UTF-8; decode UTF-8 ไม่ผ่าน → TIS-620; ผู้ใช้เปลี่ยนเองได้ในหน้าพรีวิว |
| ตัวคั่น (CSV) | `,` (ค่าเริ่มต้น), `;` หรือ tab — ตรวจจากบรรทัดหัวตาราง |
| Quote | `"` ตาม RFC 4180 (ชื่อสินค้ามี `,` หรือ `"` ได้) |
| หัวตาราง | บรรทัดแรกที่ไม่ว่าง; ข้ามบรรทัดว่างและบรรทัดที่ขึ้นต้นด้วย `#` ก่อนหัวตาราง |
| ขนาด | ≤ 5 MB, ≤ 2,000 บรรทัดข้อมูล |
| ตัวเลข | ทศนิยมใช้ `.`; ยอมรับ `,` คั่นหลักพัน (`1,250.50`) และตัด `฿`/ช่องว่าง; XLSX อ่านค่าตัวเลขจาก cell โดยตรง |
| วันที่ | `YYYY-MM-DD`, `DD/MM/YYYY` (ปี ค.ศ. หรือ พ.ศ. — ปี ≥ 2400 ถือเป็น พ.ศ. แล้วลบ 543), วันที่ของ Excel (serial) |

## 2. คอลัมน์

### 2.1 จำเป็น (required)

| Field | ชื่อหัวคอลัมน์ที่รู้จักอัตโนมัติ (ไม่สนตัวพิมพ์/ช่องว่าง) | ชนิด | กฎ |
|---|---|---|---|
| `product_code` | รหัสสินค้า, รหัส, SKU, Item Code, Material, Product Code | text ≤ 64 | ใช้ match สินค้าของร้าน (§4) |
| `product_name` | ชื่อสินค้า, รายการ, Description, Product Name | text ≤ 200 | แสดงผล / ช่วย match |
| `qty` | จำนวน, Qty, Quantity | decimal > 0, ≤ 4 ตำแหน่ง | |
| `unit` | หน่วย, Unit, UOM | text | ต้อง map เข้ากับหน่วยของสินค้า (`Product.units[].name`) |
| `unit_price` | ราคาต่อหน่วย, ราคา, Unit Price, Price | decimal ≥ 0, ≤ 4 ตำแหน่ง | ราคาทุนต่อหน่วยที่ระบุ (ก่อน VAT ถ้า `vat_flag` บอกว่า exclusive) |

### 2.2 ไม่บังคับ (optional)

| Field | หัวคอลัมน์ที่รู้จัก | ชนิด | ใช้ทำอะไร |
|---|---|---|---|
| `dn_no` | เลขที่ใบส่งของ, ใบส่งของ, DN, Delivery No | text ≤ 40 | **dedupe** (§5) → `ManualReceiptReq.deliveryNo` |
| `po_no` | เลขที่ใบสั่งซื้อ, PO, PO No, Order No | text ≤ 40 | อ้างอิง, แสดงในใบรับ |
| `delivery_date` | วันที่ส่ง, วันที่, Delivery Date | date | วันที่รับเริ่มต้น (ไม่เกินวันนี้) |
| `dealer_name` | ผู้แทนจำหน่าย, ผู้ขาย, Vendor, Supplier | text | ช่วยเลือก vendor (match ชื่อ/เลขผู้เสียภาษี) |
| `vat_flag` | VAT, ภาษี, Price incl VAT | `Y`/`N`, `inc`/`exc`/`none`, `รวม`/`ไม่รวม` | ราคาในไฟล์รวม VAT หรือไม่ (ค่าเริ่มต้นตั้งต่อร้าน: ไม่รวม) |
| `invoice_no` | เลขที่ใบกำกับ, Invoice No | text | → `ManualReceiptReq.vendorInvoiceNo` (ถ้าไม่มี ผู้ใช้กรอกตอนยืนยัน) |
| `line_discount` | ส่วนลด, Discount | decimal ≥ 0 | ส่วนลดต่อบรรทัด (บาท) |

คอลัมน์อื่นถูกเก็บไว้แสดงในพรีวิวและไม่นำเข้า

## 3. Column mapping ที่จำไว้ต่อร้าน

1. ครั้งแรก: ระบบเดา mapping จากหัวคอลัมน์ (§2) แสดงหน้าจับคู่ให้ผู้ใช้แก้
2. เมื่อนำเข้าสำเร็จ บันทึก **profile** ต่อร้าน: `import_profiles(tenant_id, kind='delivery', name, header_signature, mapping jsonb, encoding, delimiter, vat_flag_default, vendor_id?)`
   - `header_signature` = SHA-256 ของรายชื่อหัวคอลัมน์ (normalize: trim, lower-case, เรียงตามตำแหน่ง)
3. ครั้งถัดไปไฟล์ที่ signature ตรงกัน → ใช้ profile อัตโนมัติ (ผู้ใช้ยังเห็นพรีวิวก่อนยืนยัน); มีได้หลาย profile ต่อร้าน (เช่น แยกตามผู้แทนจำหน่าย)
4. จำ mapping **รหัสสินค้าในไฟล์ → สินค้าของร้าน** ด้วย: `product_code_aliases(tenant_id, vendor_id null, external_code, product_id, unit_map jsonb)` เพื่อให้ไฟล์ถัดไปไม่ต้องจับคู่ซ้ำ
5. Profile และ alias แก้/ลบได้ในหน้าตั้งค่านำเข้า (สิทธิ์ `data.import`); ทุกการเปลี่ยนเข้า audit log

## 4. การ match สินค้าและหน่วย

ลำดับการหาสินค้าต่อบรรทัด:
1. `product_code_aliases` (vendor ที่เลือก → ทั่วไป)
2. `Product.sku` ตรงทุกตัวอักษร (ไม่สนตัวพิมพ์)
3. `Product.barcode`
4. ไม่พบ → บรรทัดสถานะ "ยังไม่ผูก" ผู้ใช้ค้นสินค้า/สร้างสินค้าใหม่ แล้วระบบจำเป็น alias

หน่วย: match `unit` กับ `Product.units[].name` (normalize ช่องว่าง, คำพ้อง เช่น `ถุง`=`bag`, `แผ่น`=`sheet`) → `unitIdx`; ไม่พบ → ผู้ใช้เลือก แล้วจำใน `unit_map`

ราคา → ต้นทุนต่อหน่วยฐาน: `unitCost = unit_price / factor` (ถ้า `vat_flag` = รวม VAT และร้านจด VAT: หาร 1.07 ก่อน)

## 5. Dedupe ด้วยเลขที่ใบส่งของ

- ไฟล์ 1 ไฟล์อาจมีหลาย DN → สร้าง **ใบรับของร่าง 1 ใบต่อ 1 `dn_no`** (เหมือน BR-01 ของ cloud)
- ไม่มี `dn_no` → ทั้งไฟล์เป็น 1 ใบ และผู้ใช้ต้องกรอกเลขที่ใบส่งของก่อนยืนยัน (`ManualReceiptReq.deliveryNo` เป็น required)
- **`dn_no` ที่เคยนำเข้าหรือรับแล้วในร้าน (เทียบ `stock_docs.delivery_no` และใบร่างที่ค้าง) → ไม่สร้างซ้ำ** แสดง "DN 8100234561 รับแล้วใน GR2610-0005 เมื่อ 20/10/2569" และข้ามบรรทัดเหล่านั้น; ผู้มีสิทธิ์ `inv.receive` เลือก "นำเข้าซ้ำ" ได้พร้อมเหตุผล (audit)
- ไฟล์เดิมทั้งไฟล์ (SHA-256 ของเนื้อไฟล์ตรงกัน) → เตือน "ไฟล์นี้นำเข้าแล้วเมื่อ …"
- Server ยังมี unique `stock_docs (tenant_id, vendor_id, vendor_invoice_no)` เป็นชั้นสุดท้าย (มีอยู่แล้ว)

## 6. Validation

| ระดับ | กฎ | ผล |
|---|---|---|
| ไฟล์ | นามสกุล/ขนาด/จำนวนบรรทัด, encoding อ่านได้, มีหัวตาราง | ปฏิเสธทั้งไฟล์ |
| ไฟล์ | ขาดคอลัมน์ required หลัง mapping | ให้ผู้ใช้ map ก่อนดำเนินการ |
| บรรทัด | `qty` ไม่ใช่ตัวเลข / ≤ 0 | error บรรทัดนั้น |
| บรรทัด | `unit_price` ติดลบ / ไม่ใช่ตัวเลข | error |
| บรรทัด | `product_code` ว่าง | error |
| บรรทัด | สินค้าไม่พบ / หน่วยไม่พบ | "ยังไม่ผูก" — ยืนยันใบนั้นไม่ได้จนผูกครบ |
| บรรทัด | สินค้าเป็น `service` | error (รับเข้าสต็อกไม่ได้) |
| บรรทัด | ราคาต่างจากต้นทุนล่าสุด > 30% | warning |
| บรรทัด | รหัสสินค้าซ้ำใน DN เดียวกัน | warning (รวมหรือแยกบรรทัดได้ — ระบบใช้ moving average ตาม F7) |
| ใบ | `delivery_date` ในอนาคต | error |
| ใบ | vendor ไม่ได้เลือก/หาไม่พบ | ผู้ใช้เลือกก่อนยืนยัน |
| ใบ | `dn_no` ซ้ำ | §5 |

ผลการตรวจแสดงเป็นพรีวิว: แถวเขียว (พร้อม), เหลือง (warning), แดง (error) พร้อมดาวน์โหลด "ไฟล์ error" (CSV เดิม + คอลัมน์ `error`)

## 7. หลังนำเข้า

ใบรับของร่างไปอยู่หน้า "ซื้อเข้า / รับของ" — ผู้ใช้ตรวจจำนวนรับจริง/เสียหาย/คลัง/ส่วนลดท้ายบิล แล้วยืนยัน → `POST /api/stock/receipts` (`ManualReceiptReq`):

| ไฟล์ | `ManualReceiptReq` |
|---|---|
| vendor ที่เลือก / `dealer_name` | `vendorId` |
| `invoice_no` (หรือกรอก) | `vendorInvoiceNo` |
| `dn_no` (หรือกรอก) | `deliveryNo` |
| คลังที่เลือก | `warehouseId` |
| สินค้าที่ match, หน่วย | `lines[].productId`, `lines[].unitIdx` |
| `qty` (แก้ได้) | `lines[].qty` |
| `unit_price` (หลังแปลง VAT/ส่วนลดบรรทัด) | `lines[].unitCost` |
| ผู้ใช้กรอก | `billDiscount` |

สต็อกเพิ่มเมื่อยืนยันเท่านั้น (เหมือน cloud) ทุกการนำเข้าและยืนยันเข้า audit log (BR-18)

- **AT-OP-01** นำเข้า `samples/delivery-sample.csv` (UTF-8 BOM) → ใบรับของร่าง 2 ใบ (DN `8100234561`, `8100234577`) และ 1 ใบไม่มี DN ให้กรอกเลข
- **AT-OP-02** ไฟล์เดียวกันบันทึกเป็น TIS-620 → ชื่อภาษาไทยถูกต้อง
- **AT-OP-03** นำเข้าครั้งที่สองด้วยหัวคอลัมน์เดิม → ใช้ mapping เดิมอัตโนมัติ และสินค้าที่ผูกไว้ไม่ต้องผูกซ้ำ
- **AT-OP-04** นำเข้า DN `8100234561` ซ้ำหลังยืนยันแล้ว → ข้ามพร้อมข้อความอ้างอิง GR เดิม ไม่มีสต็อกเพิ่ม
- **AT-OP-05** บรรทัด `qty = -5` และ `unit_price = abc` → แสดง error เฉพาะบรรทัด ดาวน์โหลดไฟล์ error ได้
- **AT-OP-06** `vat_flag = Y`, ราคา 129.47, ร้านจด VAT → `unitCost = 121.00`
- **AT-OP-07** XLSX ที่วันที่เป็น Excel serial และปี พ.ศ. ในข้อความ → แปลงวันที่ถูก
- **AT-OP-08** `node scripts/check-onprem.mjs` ผ่านบน on-prem bundle ที่มีฟีเจอร์นี้
